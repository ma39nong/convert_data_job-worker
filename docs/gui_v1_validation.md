- 桌面/应用菜单启动器。已有 GUI 重复打开会复用界面，不启动第二套进程。

## 合理默认值与假设

1. GUI 采用本机浏览器前端与 Python 后端，避免额外依赖 Qt/Node 桌面打包。页面在本机回环地址，不部署公共网站。
2. 每任务是一种手型、一个场景，可同时有 A/B；两台服务器的连接设置共用，四个目标目录按任务独立设置。未来其他项目可浏览、手动填目录；当前只生成 tomato 的测试数据，不修改其他训练项目。
3. 新任务建立独立空测试输入。初次包含已有录制、原包验证后释放都提供显式开关。现场验收示例关闭删除，以便复查；新建任务的删除初值沿用原后台行为。
4. 正式仍 24h 滚动封存，首次处理前稳定观察 60 秒。没有在产品中加入假进度或提前封存按钮。
5. 修改路径会进入独立配置版本，不自动搬运旧队列/成品；只改名称仍使用原队列。第一版可通过显示的记录路径查阅旧版本，未加历史版本切换器。恢复旧目标可恢复相同配置版本。
6. 停止是安全收尾。关闭网页不代表停止，重新打开可接管；机器重启默认等待用户打开 GUI 并开始，不在后台静默扫描。
7. normal/speedup 新根分离，不能声称跨根一次原子提交；分别发布且两版完成后同步双版本完成记录到两侧 `.workflow-pairs`，GUI 才计为已发布。
8. 修改正式输入前建议新建自己的任务并保存。当前保留两套已完成且已停止的合成数据示例，方便后续改界面和路径。
