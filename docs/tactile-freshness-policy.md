# Sharpa触觉新鲜度开关

## 使用

仓库的 `configs/sharpa.yaml` 显式设置 `tactile_freshness_check: true`，保持原有150ms严格门槛。显式改为 `false` 才只针对Sharpa的20路触觉（左右手各5指，每指形变/力矩）关闭样本过旧造成的输出无效门控。更改配置前正常停止任务、等待作业收尾后再启动。布尔字符串等无效配置会报错。

显式关闭时，30Hz输出保持因果取样：当前网格行选择最近且不晚于它的真实样本，允许其年龄超过默认150ms；样本值可能重复，不插值、不推测或重写时间。独立逐行来源校验继续检查所选值完全相等及不存在未来样本。报告的 `alignment.tactile_freshness` 保存开关、门槛、每通道过旧帧数、不可用帧数和实际最大年龄。

仍要求通道存在、有样本、正确类型、有效形状/图像编码、有限力矩。首条真实样本之前不能用未来帧补值，仍裁去无效边缘；完全缺失不伪造零值。深度、RGB、关节、命令、接管状态及静止清洗条件不变。该开关不撤销采集端collection_state的失败记录，也不是跳过文件结构、消息计数或来源哈希校验。

## 历史与队列

缺少开关的旧配置/数据清单继续按严格新鲜度校验；新默认Sharpa YAML同样显式开启。单条job/数据清单持久保存实际配置；旧数据不改写。capture/ingest长期队列的身份计算仅排除此策略字段，防止只改策略就丢失旧容器身份或重扫输入。输入/输出路径、其它配置和质量参数仍参加原身份计算。更改此开关不会改变既有capture队列身份。

已完成/已排除记录不会自动重处理；未执行任何历史批量重试、原包清理或远端数据改写。新策略只在新处理使用。

## 验证范围

触觉单测覆盖形变/力矩断流：关闭时通过，开启时内部间隙拒绝；旧缺字段等同严格模式；真实时间戳不变；深度间隙仍拒绝；第一条触觉之前无未来补值。真实CDR/SQLite小样本删去20通道中间消息后，实际写Parquet/视频、计算统计并经独立来源逐行回读比对通过；同源开启严格门槛仍拒绝。另检查布尔类型和长期队列身份/单条配置证明区别。
