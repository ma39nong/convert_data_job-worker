# 单包串行的 NVMe 临时工作区对照试验

本工具只测临时工作区所在存储的影响，不启用多包并发，不修改正式源码、配置、队列或训练输出。正式接收器会先在当前包发布并清理后进入维护；试验结束后，仅恢复本工具自己发起的维护请求。其他操作者已有或后来修改的维护请求会保留。

## 运行方式

在服务器本机，使用现有接收器虚拟环境执行 `scripts/nvme_trial.py`。默认先只检查条件；加 `--run` 才实际进入维护和开始试验。工作站 SSHFS 环境会被拒绝。无需安装依赖或修改挂载。

```bash
/path/to/server/project/.venv/bin/python scripts/nvme_trial.py \
  --project /path/to/server/project --robot sharpa --group A \
  --episode episode123 --nvme-root /data1 --order abba --run
```

`--episode` 必须是正式队列中已经 published、原始数据仍完整且内容未变化的一包。试验还会完整检查实际输入，确认内容身份与已发布来源一致。不同录制不能作为同包对照。输入不会复制、改写或删除。

NVMe 自动从 `/data1`、`/data2` 选择可写、空闲空间足够且挂载源确为 `/dev/nvme...` 的位置，也可用 `--nvme-root` 指向这些盘上的可写子目录。权限或空间不足会在请求维护前退出，不自动 sudo、更改权限或清理其他数据。

## 对照设计

同一份正式源码、配置和消息定义复制到两个独立试验工程中。A 的工程与工作区在原 `/data` 存储，B 在 NVMe；两者仍从原 `/data` 读取同一原始 bag，试验结果都发布到 `/data` 的独立试验目录。原有 job 输出路径、工作区所有权、文件变化检测及清理限制保持生效，不通过符号链接绕过限制。

默认顺序 **A→B→B→A**，每次只处理一包。这样可减少顺序偏差，但不清系统缓存，也不控制无关任务的存储负载，不能宣称完成严格冷缓存基准。`--order ab` 可以缩短为初步两次试验，但第二次可能从缓存预热中受益。

正式接收器保持存活且维护中，试验协调器持有独占锁，防止重复启动两个对照。Ctrl+C/SIGTERM 请求取消后，先等待当前试验包结束，再停止启动下一次并恢复自己持有的维护请求。强制 SIGKILL 或断电无法执行恢复，此时应检查试验进程结束情况，再用正式接收器 `resume` 恢复；不能仅因终端断开就并行重跑。

## 计时与质量验证

每次真实执行接收检查、只读直接源输入、静止段裁剪、转换、完整来源和视频校验、最终所有原始文件哈希、隔离发布复制/哈希/完整视频验证以及临时清理。转换 worker 数保持为1。

每个进度事件保留单调时钟，按互不重叠的阶段汇总：

- `input_check`：SQLite、消息计数、源哈希及必需流解析。
- `cleaning`：静止识别、全部话题清洗重写和输出检查。
- `conversion`：从清洗 bag 建立索引并写出训练数据。
- `output_verification`：完整视频、独立来源及无损传感器对比。
- `final_source_hash`：发布前所有原始文件最终核验。
- `archiving`、`publication`、`cleanup` 以及其余小量 `other`。

维护等待、源码准备和组间结果对比不计入单包处理时间；正式目录扫描与60秒稳定观察也不计入本试验，因为来源是已发布且重新完整核验的固定原始包。每次是隔离的单来源数据集发布，未模拟不断增长的正式批次元数据继承成本。

全部试验完成后，另比较源身份、完整裁剪映射、特征/帧数、全部 Parquet 数值和三路 RGB 视频文件 SHA256。任意差异均判失败，不将“更快但结果不同”视为成功。各阶段 `A均值-B均值` 为正表示 NVMe 更快，负表示该阶段本轮没有收益。

预计清洗重写、读取清洗包进行转换和来源校验更可能受益；原始输入检查/最终源哈希仍访问原盘，未必改善；跨盘发布仍要向原盘写入，可能变慢。判断依据是全流程和分阶段实测，不是单看 NVMe 顺序读写带宽。

## 结果位置

正式工程旁的 `code/experiments/nvme-时间-标识/` 保存 summary.json、逐次日志、阶段事件、源码哈希和独立试验数据集。NVMe 的 `auto-clean-convert-trials/` 保存小型源码副本；每次清洗中间包按既有所有权规则清理。不会删除试验最终数据或清理其他任务目录。

本地测试验证计时无重复归属、维护请求所有权、旧 drained 状态不能提前放行、独占试验锁、挂载/容量检查，以及 Wuji 和 Sharpa 的两份源码工程通过实际 subprocess 执行接收/清洗/转换/校验/发布，且原始内容不变、输出数值和视频一致。此测试是正确性验证，不是服务器 NVMe 性能结果。
